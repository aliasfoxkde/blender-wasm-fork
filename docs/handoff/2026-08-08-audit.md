# Audit: Blender WASM Fork

Date: 2026-08-08

## What Was Checked

Commands:

```bash
git status --short --branch
git log --oneline --decorate -5
git remote -v
find . -maxdepth 3 -type f
sed -n '1,260p' Makefile
sed -n '1,260p' .github/workflows/build-release.yml
sed -n '1,220p' demo/vite.config.js
```

## Findings

### F1: Repository Is Upstream-Focused

The root README was minimal and upstream-oriented. It did not explain the greenfield product plan or handoff process.

Fix applied:

- replaced root `README.md` with product/build/handoff overview.

### F2: No Agent Instructions

No `CLAUDE.md` or `AGENTS.md` existed.

Fix applied:

- added `CLAUDE.md`;
- added `AGENTS.md`.

### F3: Origin Remote May Be Unsafe

Observed local remote:

```text
origin https://github.com/HeyPuter/blender-wasm.git
```

This is upstream, not the user's fork. The agent must set the user's fork as `origin` before pushing.

Fix applied:

- documented exact remote correction command.

No remote was changed because the user's fork URL was not provided.

### F4: Demo Has Dev Headers But Needs Static Deploy Headers

`demo/vite.config.js` sets cross-origin isolation headers for dev/preview. Cloudflare Pages also needs static `_headers`.

Fix applied:

- added `demo/public/_headers`.

### F5: Heavy Build Is Already Documented As Expensive

The upstream workflow warns the build can take hours, many GB, and swap headroom.

Policy:

- do not run heavy builds locally by default;
- add fast CI first;
- use manual/self-hosted builder for artifact builds.
